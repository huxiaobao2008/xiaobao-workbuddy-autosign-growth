# 踩坑清单（都是真踩过、白烧过时间的）

## 接口层

1. 签到接口必须用 **POST**；GET 探测 `/v2/billing/meter/*` 返回 404，容易误判"路径不对"。
2. 域名以登录态 `auth.domain` 为准；写死 `copilot.tencent.com` 会 404。
3. 旅行接口域名是 `www.workbuddy.cn` 且**不带 /v2**，与签到域名/前缀都不同，混用一律 404。
4. `code=10001` 是"今日已签"，不是错误，不要重试。
5. 登录态约 60 天失效，失效后唯一解法是客户端重新登录。

## 客户端自动化层

6. **静态下标召唤专家团必错**——服务端会整表换名单与顺序（实测旧下标 idx=7 点到的
   是完全不同的团队）。必须运行时读名单、按名字召唤。
7. **确认框不弹 = 不计分**。suppress 键被写成 true 时召唤直接跳过确认框；
   手动召唤没有"清键"这一步，所以手动测试常常永远不计分。
8. **轮次没跑完就判定 = 误报失败**。阶段型团队 15 分钟以上很常见，且有"驱动退出后
   自行跑完并延迟计分"的真实案例（跨夜计分）。
9. 让路给用户（用户在打字）导致的跳过**不算尝试**，不能写进历史账本，
   否则会把候选池慢慢封死。
10. 前置步骤瞬时失败（确认框没点掉等）也不算尝试，否则会永久拉黑可用团队。

## 清理层

11. 侧边栏标题会被**截断**（"…执行规则：如果上面的任务…" 常显示成 "…执行规则"），
    长指纹匹配不到，短指纹才安全。
12. 清理**绝不能**用"任务特征词"匹配会话——用户自己开的会话会命中，会误删。
13. 切号后立刻读会话列表会读到空（侧边栏还没渲染），造成"删 0 条"假象；
    必须等列表出现再操作。不 reload 的切号经常校验失败。
14. 正在使用的会话删不掉（天然保护），清理前不必特别处理当前会话。

## 调度层

15. 按配置顺序跑会让"已完成 16/19 的尖子号"先跑完时间和额度，
    只完成 6/19 的落后号永远轮不到——必须按完成数升序排。
16. 报表以"驱动跑过"为准会虚报（UI 显示都跑完，服务端只完成 6/19）。

## 工程层

17. 编辑器偶尔出现"报告成功但未落盘"（同一天遇到两次），
    关键改动后必须回读文件确认，不能只看工具返回。
