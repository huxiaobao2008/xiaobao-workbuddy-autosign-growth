# Buddy加油站全自动

## 一、目的

把 WorkBuddy「Buddy 加油站」的日常运营（签到、成长任务、积分、盲盒、猫猫旅行）从手工点击
变成可重复执行的一条流水线，并支持多账号批量调度。

两条链路：

- **API 直签链路**：签到、成长任务清单、成长伙伴状态、能量/盲盒、猫猫旅行——只需登录态 Token，
  不点击任何界面（脚本自带，零第三方依赖）。
- **客户端自动化链路**：专家团召唤、模板任务、画布等**只能由客户端本体触发**的任务——
  通过 CDP 驱动桌面客户端完成（成长任务进度由服务端检测真实产品使用事件，网页/接口造不出来）。

## 二、适用时机

在下列场景启动本技能：

- 要求每日/批量完成签到与积分领取；
- 要求推进「成长计划」任务（召唤专家团、模板对话、画布、自动化、技能等）；
- 要求开盲盒、派猫猫旅行、领取旅行奖励；
- 要求多账号按顺序跑完且如实汇报每个账号的真实完成度。

不适用于：网页版（无签到入口，仅 PC 客户端）、需要付费确认的任务（默认跳过）、
需要微信扫码等外部动作的任务（桌面端无路径，直接跳过）。

## 三、执行步骤

### 步骤 1 · 读取登录态并校验

- 动作：定位登录态文件 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info`，
  读取 `auth.accessToken` 与 `auth.domain`；多账号时按 `config.json` 的 `accounts` 逐个载入凭证。
- 判据：Token 存在且未过期；缺失时提示用户在客户端重新登录，不伪造、不猜测。

### 步骤 2 · 确定账号执行顺序（关键）

- 动作：先用接口拉取每个账号的成长任务完成数，按**完成数从少到多**排序后再执行。
- 判据：日志输出顺序形如 `account_m 6/19 → account_n 6/19 → … → account_d 17/19`；
  排序错误的是"尖子号先跑、落后号永远轮不到"的老问题。

### 步骤 3 · 跑 API 链路（每个账号）

- 动作：依次调用签到状态、领取签到、成长任务清单、成长伙伴状态、能量/盲盒配额、
  旅行状态与派遣；随后做成长热度点亮（云端会话）。
- 判据：每个动作返回 `code=0` 或幂等跳过（已签到返回 `code=10001` 属正常，不是错误）。

### 步骤 4 · 跑客户端链路（仅当该账号仍有可推进任务）

- 动作：切号到目标账号（切换后校验界面昵称与凭证一致），再驱动 UI 任务；
  专家团任务按**运行时真实卡片名单 + 团队名**召唤（禁止用硬编码下标）。
- 判据：召唤后必须出现「积分消耗提醒」确认框并勾选确认——**确认框没弹 = 授权事件没发 = 不计分**；
  团队轮次必须跑到自然收尾（阶段型流程可达 15 分钟以上），进度未变时先宽限轮询再判失败。

### 步骤 5 · 收尾领取与真相对账

- 动作：全量扫一遍可领积分并领取；随后以服务端返回为准输出每个账号的
  `已完成/总数` 与未完成项清单。
- 判据：报表只认服务端数字，禁止以"驱动跑过"冒充"任务完成"。

### 步骤 6 · 达标后清理遗留会话

- 动作：仅当该账号**成长任务全部完成**（付费/过期/锁定/桌面端做不到的不算遗留）
  **且无可领积分**时，才删除自动化产生的会话；未达标一律保留。
- 判据：清理只按自动化指纹匹配（会话标题含自动化追加的指令文本），
  禁止用"任务特征词"匹配（会误删用户自己的会话）。

### 步骤 7 · 循环直到全部完成

- 动作：一轮跑完后复核所有账号；仍有未完成账号就进入下一轮（默认最多 3 轮），
  全部完成才收工。
- 判据：每轮日志有复核输出；未手动停止时不提前收摊。

## 四、输出规范

- 用一句话起头汇报：本次覆盖账号数、签到与积分到账、成长任务真实完成度。
- 每个账号单列一行：`账号 → 服务端进度 X/N｜未完成 N 项：…｜本次到账 N 积分`。
- 失败项写明原因与处理办法（登录态失效 / 付费未确认 / 桌面端做不到 / 达每日上限）。
- 禁止输出 Token、密钥等任何凭据。

## 五、边界与降级

- 付费任务默认跳过，需显式确认才执行。
- 需外部动作（微信扫码关注公众号等）的任务直接跳过并说明，不反复重试。
- 旅行接口每日派遣有上限，达上限时不发写请求。
- 客户端不可达时：仅跑 API 链路，UI 任务整体跳过并注明。
- 网络不可用：无法调用接口，按登录态与本地配置给出可执行步骤，不编造结果。

## 六、质量自检

- [ ] 账号执行顺序按完成数升序
- [ ] 专家团按名字召唤且确认框已确认
- [ ] 报表数字取自服务端而非"跑过"
- [ ] 清理发生在全部完成且无可领积分之后
- [ ] 未手动停止时不提前收工
